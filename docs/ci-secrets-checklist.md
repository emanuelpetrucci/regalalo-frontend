# CI Secrets Checklist — regalalo frontend

Configure these secrets in **GitHub → repo → Settings → Secrets and variables → Actions → Repository secrets**.

## Required Secrets

| Secret name | Description | How to get |
|-------------|-------------|------------|
| `TEST_USER_EMAIL` | Email of a test user with verified account | Create manually in staging DB |
| `TEST_USER_PASSWORD` | Password of the test user above | Set when creating the test user |

## Optional Secrets (future)

| Secret name | Description | When needed |
|-------------|-------------|-------------|
| `STAGING_BASE_URL` | Override `BASE_URL` for staging runs | When adding staging E2E job |
| `STAGING_API_URL` | Override `API_URL` for staging runs | When adding staging E2E job |

## Setup Steps

1. Go to: `https://github.com/emanuelpetrucci/regalalo-frontend/settings/secrets/actions`
2. Click **New repository secret** for each row above
3. Create the test user in the staging/test environment
4. Verify by running a test push to `develop` branch

## Notes

- `TEST_USER_EMAIL` / `TEST_USER_PASSWORD` are only used by the real-login test (`auth.spec.ts: redirige al explorar tras login exitoso`). All other active tests use stubbed responses.
- All 49 tests generated by `bmad-testarch-automate` use `test.skip()` and **do not require** these secrets until activated.
- When activating tests that use real API calls (infra tests), set `E2E_DATABASE_URL` as well — see `_bmad-output/test-artifacts/atdd-checklist-infra-e2e-backend-real-environment.md`.
